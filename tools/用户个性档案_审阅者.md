# 审阅者个性档案（从对话提炼）

## 身份标签
- 网络小说作者（有声演播场景）
- 技术敏感型写作者
- 最终决策者

## 审阅层级（优先级从高到低）

### L1 逻辑性 
- **前后矛盾零容忍**：角色行为打脸、设定前后冲突、进度倒挂，一眼揪出
- 例：发现 Ch9 龙脉骨位置与前文矛盾 → 追溯全书 → 给出统一方案
- 关注点：事件因果链是否断裂、道具/设定的跨章一致性

### L2 格式洁癖
- 正文不容杂质：`\n` 字面文本、`\"` 转义符、`【改N】`标记、修改对照表，必须清干净
- 行尾统一 LF，不要 CRLF
- 首行不要有空行/\r 残留
- 每章按"标题→空行→正文段落→空行→段落"结构

### L3 水文压缩（V1规则）
- 删"仿佛/似乎/好像/如同/像是"等多余词（V1-10）
- 删"嘴角勾起一抹"简化为"冷笑/苦笑/笑了"（V1-6）
- 删"不是……而是……"AI句式（V1-5）
- 删章尾升华/总结性段落（V1-9）
- 删"月色如水/夜色如墨"等四字套话（V1-7）
- 内心独白不堆叠，留一个最强的（V1-11）
- 比喻不扎堆，同一场景不超过2个"像……"

### L4 称呼修正
- 对照尊称表，太监/朝臣称皇子必须用"三殿下/三皇子"
- 魏征弹劾也不能直呼"李恪"
- 例外：袁道玄、内心独白、同辈互称

### L5 反馈要求
- **必须给修改汇总**：改了几处、分别在哪、改了啥、依据什么规则
- 不能只扔改完的正文不说改动
- 要告知是否有逻辑矛盾

### L6 效率要求
- 不要反复确认，不要拖流程
- 出问题自己找根因再修复，不要问"怎么办"
- 工具有编码问题自己解决，不要浪费 token 在环境问题上

## 典型情绪表达
- 不耐烦时："你在干嘛啊""你干啥呢"
- 发现问题时："你瞅瞅你搞了个啥""你自己找错误"
- 认可时："没问题了，插回去吧"
- 给方向时清晰直接，不兜圈子

## 工作流偏好
- 你（AI）做初稿/改文 → 审阅者审 → 我终审
- 每一步都要反馈摘要
- 错了自己查根因，修好再说
