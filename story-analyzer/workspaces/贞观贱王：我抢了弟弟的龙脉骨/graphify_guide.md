# Graphify 功能说明与应用场景

## 一、它能做什么

### 核心能力
- `/graphify .` → 把当前目录所有文件（代码、文档、PDF、图片、视频）建成本地知识图谱
- 跑完后产出三个文件：graph.html（交互图）、GRAPH_REPORT.md（分析报告）、graph.json（原始数据）

### 常用命令

```bash
/graphify .                    # 全量建图
/graphify . --update          # 增量更新（只扫新增/修改的文件）
/graphify . --mode deep       # 深度模式（更全面的关系抽取）
/graphify . --watch           # 监控模式，文件变了自动重建

/graphify query "问题"         # 用自然语言问图谱
/graphify path "概念A" "概念B" # 两个概念之间的最短路径
/graphify explain "概念名"     # 解释某个节点
```

### 输出内容
- **God Nodes**（神节点）—— 整个项目里连接最多的核心概念
- **Communities**（社区）—— 自动发现文件之间的主题聚类
- **Surprising Connections**（意外连接）—— 跨社区的连接，你没想到但确实存在的关系
- **Suggested Questions**（建议问题）—— 图谱自动生成的值得探索的问题

## 三、对我们改稿流程的用处

### 能解决的问题

**① 跨章节快速查信息（替代翻文件）**
- 现在：想知道"李愔在第几章出现过"→ 翻原文、翻改文、翻梗概
- 用 graphify：`graphify query "李愔在哪几章出场？各自干了什么？"` → 直接出答案
- 适用场景：写新章时检查角色前文行为、道具当前状态

**② 发现重复情节模式（重复检测）**
- 现在：14章和20章都写了"发包子收集数据"，改到20才发现
- 用 graphify：`graphify path "发包子" "收集数据"` → 看两章的关系路径是否高度相似
- 或者直接查：`graphify query "哪些章节提到了崇仁坊包子铺？"` → 一眼看到15、21、23都涉及
- 适用于**事前筛查**：跑新章前查一下相似情节是否已写过

### 不能解决的问题

| 问题 | 为什么不能 |
|------|-----------|
| Gateway 掉线 | 这是进程管理问题，跟知识图谱无关 |
| 文件追加混乱 | 这是输出提取逻辑问题 |
| 手动捞 OpenSquilla 输出 | 同上 |
| 规则碎片化 | 规则文件才几十行，建图是大炮打蚊子 |

### 总结

Graphify 在改稿流程中能帮上**查信息**和**查重复**两件事。最典型的用法：

> 准备改第N章前 → 先 `graphify query "前20章里，李恪和影七有过几次正面交锋？分别在什么场景？"` 
> → 拿到结果 → 确认新章不重复 → 再跑改文

它不是解决流程自动化问题的工具，是解决**"文件太多记不住"**问题的工具。
